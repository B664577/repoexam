# 仓库带背（repo-exam）

> 我们在让 AI 改一个它从没读懂过的仓库，然后抱怨它改错了。
>
> 本工具先出一张**答案由代码本身确定**的卷子，量出"读懂了多少"，
> 再决定要不要让它动手。考不过的，不许改代码。

第三届"兴智杯"全国人工智能创新应用大赛 · 赛题 172 代码生成效率赛

---

## 为什么要先考试

AI 写代码的失败，大多不是"不会写"，是"不知道这个仓库是怎么回事"：
改了一个函数的签名却漏掉三个调用点、
在已有工具函数的地方重新造一个、
把一个有副作用的函数当纯函数用。

这些都不是生成能力问题，是**上下文理解**问题。
而上下文理解今天没有度量——于是我们只能在它改错之后才知道它没读懂。

本工具把它变成一个考前可测的量。

## 卷子的关键性质：答案由代码确定

六类题目全部由静态分析从仓库本身生成，标准答案就是代码事实，
因此**评分是确定性的，不需要人判卷，也没有评分者偏好**：

| 题型 | 问什么 | 答案来自 |
|---|---|---|
| 定义位置 | `X` 定义在哪个文件 | AST 的函数与类定义 |
| 调用点 | 哪些文件调用了 `X` | AST 的 Call 节点 |
| 影响面 | 改 `X` 的签名会牵动哪些文件 | 调用点的传递闭包 |
| 依赖方向 | 模块 `A` 是否依赖 `B` | import 图 |
| 异常面 | `X` 可能抛出哪些异常 | AST 的 Raise 节点 |
| 副作用 | `X` 是否写文件／联网／改全局 | 可疑调用与 global 语句 |

出题时**答案不写进卷子**。卷子与答案分成两个文件，
答案文件带哈希，交卷后才用它判分。

## 两个必须讲清的边界

1. **静态分析看不见动态行为**：反射调用、`getattr` 拼出来的名字、
   插件注册、运行时猴补丁，本工具一律看不见。
   所以"影响面"是**静态可见的影响面**，不是全部影响面。
   每份成绩单上都会写明这一条，不靠措辞含糊过去。
2. **考过不等于会改**：这张卷子量的是"读懂了多少"，不是"改得对不对"。
   它能挡住没读懂就动手的，挡不住读懂了仍然改错的。

## 安装

```bash
python -m pip install -r requirements.txt   # 仅标准库，此文件为空占位
```

需要 Python 3.10 以上。不需要 GPU，不联网。

## 用法

```bash
# 1 出卷：从一个仓库生成卷子与答案
python -m repoexam make --repo ./demo_repo --out exam/ --n 20

# 2 作答：人或 AI 填 exam/卷子.json 里每题的 answer 字段

# 3 判卷：按答案评分，并给出是否允许改代码
python -m repoexam grade --exam exam/卷子.json --key exam/答案.json
```

退出码：`0` 通过（允许改代码），`5` 未达线（不允许）。

## 跑通内置演示

```bash
python demo.py
```

演示里有三位考生：**全对的**、**只会背文件名的**、**瞎猜的**。
预期：第一位通过，后两位被挡下，并指出各自错在哪一类题上。

## 目录

```
repoexam/
  __main__.py    命令行入口
  analyze.py     仓库静态分析：定义、调用、import 图、异常、副作用
  exam.py        出卷、判卷、成绩单
demo_repo/       演示用的小仓库（有意带一个漏掉的调用点）
demo.py          一条命令跑完整演示
tests/           工具自身的测试
```
